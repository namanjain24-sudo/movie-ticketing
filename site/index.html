New · live events

Not just films any more.

Matches, concerts, stand-up, theatre and workshops, sold by exactly the same booking mechanic. A showtime now names a film or an event — never both, never neither, enforced by a check constraint rather than by hope — and everything below it only ever knew a showtime id, so none of it had to change.

  • Real grounds, real stands. The Garware Pavilion and the North Stand are what is written on a Wankhede ticket. Eden Gardens has the B. C. Roy Club House; Chepauk has the I, J and K stands.
  • A stand is a price band, not a separate listing. One match is one occurrence sold six ways, so the seat map groups by band and prints the band's own price above it.
  • The ticket says where to stand. Not "VIP" — "Garware Pavilion · GP-B-4", which is the part you need at a turnstile.
  • Concerts get the front. DY Patil is divided for a gig rather than for cricket: a Fan Pit at the stage, then Gold, Premium, Silver and General behind it.

New · support agent

Help that reads your actual booking.

A support chat in the app, answered by a model on Groq — but the model is never asked what it remembers about ticketing. The API assembles the context first: this account's own bookings, and this deployment's own policy numbers straight out of env. The prompt's first rule is to answer from that and say so plainly when the answer is not in it.

  • It cannot read somebody else's ticket. The query is scoped by user id, so another customer's booking is not in the context to begin with — there is no sentence you could type that would fetch it.
  • It cannot invent a deadline. The cancellation window, the booking fee and the hold timer come from the same configuration the booking code enforces, read seconds before the question is answered.
  • The key never leaves the server. Anything prefixed EXPO_PUBLIC_ is inlined into the bundle in plain text, so a key on the phone would be sitting inside the APK. The phone talks to this API; only this API talks to Groq.
  • It still works with no key at all. Unset is a mode, not an error: the server answers from the same grounded notes and the chat says which of the two replied, rather than passing the short answer off as the considered one.

Before you install it

Why does Android warn me about this app?

Because it did not come from the Play Store. Any APK installed directly gets that warning, and you have to allow installs from this source once. The build is made from the source in this repository and carries no analytics SDK and no ad network.

Why is the first open slow?

The API runs on a free host that sleeps after fifteen minutes of quiet and takes about a minute to wake. The app waits for it and says so rather than failing, but the minute is real. Every open after that is immediate.

Is the payment real?

No. The gateway is a mock that behaves like a real one: it authorises, then confirms by signed webhook, and the booking only becomes confirmed when that webhook arrives. No card details are collected anywhere, and no money moves.

Do I have to make an account?

You can sign in as demo@example.com with the password DemoPassw0rd. Registering works too and writes to the same live database as everything else.

Does the support chat see my data?

It sees your own bookings, because that is the only way it can answer a question about one. The query is scoped to your account, so another customer's ticket is never in the context — and the model is reached by the server, never by the phone, so no key ships inside the APK. Without a key configured the chat still answers, from the same notes, and tells you that is what happened.

Why is the map blank on the cinemas tab?

It needs a Google Maps key, which the public build does not carry. The list, the addresses, the distances and the handoff to your own maps app all work without it.

What happens if I close the app mid-booking?

The hold is a real database state with an expiry, so nothing is lost and nothing is oversold. When it lapses the seats go back. If you were part way through paying, the payment settles or it does not, and either way the booking reflects what actually happened rather than what the app guessed.
