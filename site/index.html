Availability is a band, not a countdown

Plenty, filling, almost full, or sold out. Never a precise number that was only true one request ago.

Ratings are computed from reviews

One review per person, editable, never stackable. An average with three reviews behind it says three, not a rounder number.

Before you install it

Why does Android warn me about this app?

Because it did not come from the Play Store. Any APK installed directly gets that warning, and you have to allow installs from this source once. The build is made from the source in this repository and carries no analytics SDK and no ad network.

Why is the first open slow?

The API runs on a free host that sleeps after fifteen minutes of quiet and takes about a minute to wake. The app waits for it and says so rather than failing, but the minute is real. Every open after that is immediate.

Is the payment real?

No. The gateway is a mock that behaves like a real one: it authorises, then confirms by signed webhook, and the booking only becomes confirmed when that webhook arrives. No card details are collected anywhere, and no money moves.

Do I have to make an account?

You can sign in as demo@example.com with the password DemoPassw0rd. Registering works too and writes to the same live database as everything else.

Why is the map blank on the cinemas tab?

It needs a Google Maps key, which the public build does not carry. The list, the addresses, the distances and the handoff to your own maps app all work without it.

What happens if I close the app mid-booking?

The hold is a real database state with an expiry, so nothing is lost and nothing is oversold. When it lapses the seats go back. If you were part way through paying, the payment settles or it does not, and either way the booking reflects what actually happened rather than what the app guessed.
